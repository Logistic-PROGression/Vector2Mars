«Вектор на Марс»

Задача

В первой части задания вы приняли сигнал со спутника и увидели изображение маршрута для ровера, который использовать для определения кратчайшего пути не рекомендуется, он опасен. Будьте внимательны при создании алгоритма поиска и не забудьте исключить этот маршрут из конечной выборки. Ваша основная задача, используя камеру беспилотника, получить изображение с поверхности рабочего пространства со всеми маршрутами и написать программное решение с использованием компьютерного зрения для поиска кратчайшего маршрута для ровера (исключая переданный спутником).

Что считается решением?

1. Программное решение – разработанный вами алгоритм для полета БПЛА и анализа маршрутов. Исходный код на языке Python с библиотеками Pioneer SDK 2 для программирования БПЛА и OpenCV для анализа изображения. Программа также должна выдавать ответ в удобной форме о кратчайшем маршруте, его цвете и длине.
2. Отчет о проделанной работе – файл отчета о проделанной работе в свободной форме в формате DOCX (допускается отчет в формате PDF или markdown с выгрузкой в PDF).
3. Зачетный полет – ваша финальная демонстрация работы алгоритма в последний конкурсный день.

Что будет оцениваться и влиять на итоговый результат?

*   Анализ маршрутов – на рабочем поле есть несколько маршрутов, которые обладают основными характеристиками: цвет маршрута, номер маршрута, длина маршрута. Чем больше полезной информации о маршрутах вы получите, тем больше будет оценен критерий.
*   Алгоритм – посчитать и найти кратчайший путь на изображении, не тривиальная задача. От метода который вы примените для сравнения длин маршрутов, будет зависеть оценка критерия.
*   Качество программного кода – код который падает с ошибкой после запуска, никуда не годится! Ваша программа должна быть написана без ошибок времени выполнения, предусматривать различные обработки непредвиденных ситуаций и просто быть понятной и чистой, а также документированной и удобной для проверки судьями и без вашего присутствия.
*   Реальные полеты – полет квадрокоптера должен быть безопасный. Квадрокоптер не должен задевать препятствия и края безопасного воздушного пространства. При зачетной попытке, соблюдения вами техники безопасности и красивый/безопасный полет будут оценены по достоинству.
*   Отчет – отразите в отчете максимально подробно самые важные части вашего решения: идея реализации, обоснование решения, ваша команда, этапы работы, что получилось и что нет, схема работы алгоритма и т.д. Вставьте в ваш отчет инфографику, изображения с камеры с технической информацией или любые другие изображения, которые вы получите в процессе работы.

Полезные советы:

*   Любую полную информацию по программированию Пионер Мини 2, можно найти на сайте документации в соответствующем разделе.
*   В документации также можно найти ссылку на GitFlick с готовыми примерами программ для Пионер Мини 2.
*   Если ваша команда состоит из нескольких человек, лучше распределить обязанности среди всех. Кто-то пишет код, кто-то ходит с оборудованием на тестовые попытки или за полезной информацией к сетке, а кто-то пишет красивый отчет о проделанной работе.
*   Разделите задачу на подзадачи. Вам как минимум нужно будет понять, как квадрокоптер выполняет полетные миссии. Вторая большая проблема, это то, как написать минимальный скелет программы, который принимает кадр с камеры для обработки. Это может стать неплохим началом для дальнейшей работы.
