# TUI-пульт Пионер Мини 2

Терминальный пульт для ноутбука, подключённого к Wi-Fi дрона. Умеет:

- взлетать и садиться;
- двигаться вперёд/назад, влево/вправо, вверх/вниз и поворачиваться;
- показывать состояние, заряд, координаты LPS, высоту и курс;
- сохранять фото с камеры и писать журнал полёта в JSONL;
- наклонять сервопривод камеры (только при запуске на борту).

Зрение, маршруты и ArUco здесь не используются — это отдельный слой задачи 2.

## Установка на ноутбук

```bash
python3 -m pip install -r requirements.txt
python3 -m pip install "pioneer-sdk2>=0.11"
```

`pioneer-sdk2` тянется с PyPI и на ноутбуке использует RTSP-драйвер камеры,
поэтому GStreamer/`gi` не нужен. На борту дрона SDK уже установлен.

## Подключение

1. Подключите ноутбук к Wi-Fi дрона (`PMINI2-…`, пароль `geoscan123`).
2. Проверьте, что трафик к дрону идёт через Wi-Fi, а не через VPN:

   ```bash
   ip route get 10.42.0.1     # ожидается dev wlp7s0, а не happ-xray
   ```

   Если маршрут неверный: `sudo ip route add 10.42.0.0/24 dev wlp7s0`.
   Готовый переключатель — `tools/drone_net.sh status|connect|disconnect`.

3. Запустите пульт:

   ```bash
   python3 drone_tui.py
   ```

Порты по умолчанию: SDK `10.42.0.1:20556`, RTSP-камера `10.42.0.1:8554`.
Если прямой TCP к SDK закрыт, поднимите туннель и укажите локальные адреса:

```bash
ssh -N -L 20556:127.0.0.1:20556 -L 8554:127.0.0.1:8554 \
    -i ~/.ssh/id_ed22519 pioneermini@10.42.0.1

python3 drone_tui.py --tcp 127.0.0.1:20556 --camera 127.0.0.1:8554
```

## Управление

| Клавиши | Действие |
|---|---|
| `W`/`S`, `↑`/`↓` | вперёд / назад |
| `A`/`D`, `←`/`→` | влево / вправо |
| `R`/`F` | вверх / вниз |
| `Q`/`E` | поворот влево / вправо |
| `Пробел` | стоп (обнулить скорости) |
| `T` | взлёт (arm + takeoff) |
| `L` | посадка |
| `P` | фото в `photos/` |
| `[` / `]` | камера вниз −90° / горизонт 0° (только на борту) |
| `1` / `2` / `3` / `4` | камера: вниз −90° / −60° / −30° / горизонт 0° |
| `+` / `-` | скорость 0.1…1.5 м/с |
| `V` | окно с камерой (нужен GUI) |
| `H` | полная справка |
| `X` | выход с автоматической посадкой |

Команда скорости живёт 0.35 с и обновляется, пока клавиша повторяется
терминалом. Отпустили клавишу — ось сама обнуляется; потеря связи или
закрытый терминал не оставят дрон лететь по старой команде.

## Режимы запуска

```bash
python3 drone_tui.py --dry-run     # симуляция: можно смотреть интерфейс без дрона
python3 drone_tui.py               # ноутбук в Wi-Fi дрона
python3 drone_tui.py --local       # на борту, через ssh или code-server :9999
python3 drone_tui.py --no-camera   # только полёт, без RTSP
```

Полезные параметры: `--speed 0.3`, `--max-speed 1.0`, `--max-altitude 2.5`,
`--photo-dir photos`, `--log-dir logs`.

## Камера

- Поток и фото работают с ноутбука: SDK открывает `rtsp://10.42.0.1:8554/maincamera`.
- На борту SDK сам переключается на локальный GStreamer-драйвер (даже без `--local`), потому что `GstreamerCamera` не принимает `camera_ip`.
- Наклон камеры (`ServoCamera`) ходит через Unix-сокет `/tmp/servo.sock`,
  поэтому с ноутбука недоступен. Для наклона запустите `--local` на борту
  (терминал в code-server `http://10.42.0.1:9999` или ssh).
- Углы в интерфейсе — **физические**: `0°` — горизонт, `−90°` — строго вниз.
  Шкала SDK другая: горизонт это `+30`, «вниз» — `−80`. Пересчёт линейный по
  двум точкам; если на вашем борту числа иные, задайте их флагами
  `--servo-zero <угол SDK для горизонта>` и `--servo-down <угол SDK для "вниз">`.
- Угол отправляется целым числом градусов: дробные значения борт игнорирует.
- `set_angle()` в SDK не читает реальный угол: `True` означает только то, что
  команда ушла в сокет. Пульт отправляет её с приоритетом `HIGH` (по умолчанию)
  и повторяет трижды; при необходимости приоритет меняется флагом
  `--servo-priority low|medium|high`.
- Если камера не двигается, прогоните диагностику без TUI:

  ```bash
  python3 drone_tui.py --local --servo-test
  ```

  Скрипт проводит сервопривод от −80° до +30° с паузами. Если он не двигается
  и там — дело не в пульте: проверьте питание/кабель сервопривода и что
  `/tmp/servo.sock` существует (`ls -l /tmp/servo.sock`).
- `V` открывает окно OpenCV; на headless-машине оно отключится само.

## Журнал и фото

- `logs/flight_ГГГГММДД_ЧЧММСС.jsonl` — по одному JSON на строку: подключение,
  команды, телеметрия раз в 2 с, взлёт/посадка, фото, ошибки.
- `photos/photo_….jpg` — снимки с камеры.
- Оба каталога — артефакты, в git не попадают.

Для построения статичного маршрута в журнале есть:

- `takeoff_complete` — высота после взлёта и высота точки взлёта;
- `telemetry` раз в секунду: `x`, `y`, `z`, `yaw_deg`, `altitude_m`,
  `altitude_gain_m` (подъём над точкой взлёта) и накопленная `path_length_m`;
- `flight_summary` при выходе: длительность, число точек, высота взлёта,
  максимум, подъём, длина пути, старт и финиш.

Пример строки:

```json
{"ts": "2026-11-19T12:29:39.804", "event": "telemetry", "state": "IN_SKY", "battery_v": 8.2, "x": 0.0, "y": 0.0, "z": 1.0, "yaw_deg": 0.0, "altitude_gain_m": 1.0, "path_length_m": 0.0}
```

Маршрут строится по парам `x`/`y` из событий `telemetry`, а `altitude_gain_m`
показывает, на сколько дрон поднялся над точкой взлёта.

## Автоматическая фото-миссия

`photo_mission.py` выполняет один вылет без интерактива: камера вниз (−90°),
взлёт, набор высоты 2.7 м над точкой взлёта, перелёт к точке (0.5, 0.5) м от
неё с 5 остановками (0, 25, 50, 75 и 100% пути), фото на каждой остановке по
курсу и после разворота вправо на 45° и 90°, снижение и полная посадка в
конечной точке.

```bash
python3 photo_mission.py --dry-run
python3 photo_mission.py --local
python3 photo_mission.py --local --altitude 3.0 --settle 2.0
python3 photo_mission.py --local --target-x 1.0 --target-y 1.0
python3 photo_mission.py --local --stops 1   # одно фото в конечной точке
python3 photo_mission.py --local --no-turn-photos  # без разворотов
python3 photo_mission.py --local --turn-angles 0 -90  # только вправо на 90°
python3 photo_mission.py --local --annotate-all  # разметка всех кадров
python3 photo_mission.py --local --expect-arrows  # сверить число стрелок
```

- На остановке дрон фотографирует по курсу подхода, затем разворачивается
  вправо на 45° и 90° и снимает ещё два кадра, после чего возвращается на курс
  подхода и продолжает маршрут. Углы задаёт `--turn-angles` (по умолчанию
  `0 -45 -90`; отрицательные — вправо, первый угол обязан быть 0), выключить
  развороты — `--no-turn-photos`.
- Разворот — закрытый контур по yaw из LPS: `--yaw-speed` (30 °/с),
  `--yaw-tolerance` (3°), `--yaw-settle` (1 с) и `--yaw-timeout` (20 с) на один
  разворот. Курс снимается один раз после набора высоты, поэтому ошибка
  возврата не накапливается от остановки к остановке. Без yaw в телеметрии на
  остановке остаётся одно фото (`turn_unavailable` в журнале); потеря yaw во
  время разворота — аварийная посадка.

- Наклон камеры работает только на борту, поэтому для съёмки строго вниз нужен
  `--local`; с ноутбука миссия выполнится без наклона и предупредит об этом.
- Высота добирается закрытым контуром: точка взлёта запоминается, цель —
  «земля + `--altitude`». Источник — LPS, при его отсутствии барометрическая
  высота.
- Перелёт к `--target-x`/`--target-y` — тоже закрытый контур по LPS: координаты
  точки взлёта запоминаются после взлёта, тело-фиксированные скорости
  поворачиваются на текущий yaw, высота удерживается. Допуск —
  `--move-tolerance`, скорость — `--move-speed`, таймаут — `--move-timeout`
  (на каждый отрезок).
- `--stops N` задаёт число остановок с фото: путь делится на равные шаги от
  точки взлёта (0%) до цели (100%). Пять остановок дают 0, 25, 50, 75 и 100%,
  поэтому даже если на последней кадр обрезан краем, на предыдущих поле видно
  целиком. `--stops 1` возвращает одно фото в конечной точке.
- После посадки кадры анализируются: кадры без ArUco-меток отбрасываются,
  остальные совмещаются по центрам общих меток (гомография, проверка по углам
  меток), и голосование идёт **по каждой стрелке**: позиция настоящая, если её
  подтвердили 2 кадра из 3 (3 из 5). Кадр с потерянной стрелкой или светлым
  пятном не портит итог. Опорный кадр размечается в `<фото>_annotated.png`,
  `--annotate-all` размечает ещё и каждый исходный кадр в
  `<фото>_annotated_frame.png`. Маршруты печатаются по возрастанию длины,
  дополнительно выводится 2-й по длине — ответ задания 2. Если сшить кадры
  нельзя, используется лучший одиночный кадр.
- `--expect-arrows [N ...]` — необязательная тихая проверка числа стрелок:
  без чисел ожидает 13 8 3. Для сшивки остаются только кадры с 4 метками, где
  набор чисел стрелок на маршрутах совпал с ожидаемым. Если совпадений нет,
  анализ идёт как без флага; в консоль проверка ничего не печатает, только
  событие `arrow_hint` в журнале.
- Переключатели можно включить заранее в коде: `CODE_DEFAULTS` в начале
  `photo_mission.py`, например
  `CodeDefaults(annotate_all=True, expect_arrows=(13, 8, 3))` или
  `CodeDefaults(turn_photos=False)`. Числовые параметры миссии задаются в
  `MissionConfig`.
- Фото повторяется до `--photo-retries` раз на каждой остановке. Ошибка на
  любом шаге и Ctrl+C приводят к аварийной посадке.
- Все флаги со значениями по умолчанию перечислены в шапке
  `photo_mission.py`; журнал — `logs/flight_*.jsonl`, фото — `photos/`.

## Безопасность

- Пульт не заменяет штатный пульт: держите его под рукой, тумблер SWB внизу.
- Автопилот требует «наличие пилота»; иначе задайте `Copter_flyWithoutRc = 1`
  в Pioneer Station.
- При выходе по `X` пульт сначала обнуляет скорости, затем сажает дрон.
- Защита по высоте не даёт набирать выше `--max-altitude` (по умолчанию 3 м).
- При потере кадра или телеметрии полёт продолжается: ошибки только пишутся
  в журнал и строку статуса.

## Ограничения

- Запись видео в файл пока не реализована: есть фото и просмотр потока.
- Наклон камеры с ноутбука невозможен из-за Unix-сокета в SDK (см. выше).
- Автоматическая фото-миссия есть (`photo_mission.py`); миссии по маршрутам — следующий слой.
