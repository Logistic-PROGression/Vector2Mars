# План работ: этап 2 (БПЛА + OpenCV)

Цель — несколько человек работают одновременно, не мешая друг другу. Достигается
тремя вещами: **замороженные интерфейсы**, **владение файлами** (один файл — один
владелец) и **независимые проверки** на синтетике, пока нет реальных кадров.

## 0. Контракт (менять только через интегратора)

Пока контракт не заморожен, параллельная работа невозможна. Считаем эти
сигнатуры стабильными; изменения — только аддитивные (новые поля с дефолтами)
и только после ревью интегратора.

| Модуль | Публичный интерфейс |
|---|---|
| `mars/config.py` | `RouteSpec(name, number, hsv_ranges, dangerous)`, `SceneConfig(routes, px_per_meter, min_area_px)`, `load_config(path)` |
| `mars/vision.py` | `analyze_frame(image_bgr, config) -> SceneResult`, `annotate(image_bgr, result)`, `skeleton_length_px(mask)` |
| `mars/vision.py` | `SceneResult(routes, shortest, excluded)`, `RouteMeasurement(name, number, length_px, length_m, area_px, dangerous)` |
| `mars/flight.py` | `FlightAdapter.connect/takeoff/goto/capture_frame/land/close` |
| `main.py` | `--frame`, `--config`, `--json`, `--debug-out`; exit 2 на нечитаемый вход |

Правило: **никто не редактирует чужие файлы**. Нужно изменение в чужом
модуле — сначала issue/PR-комментарий владельцу.

## 1. Дорожки и владение файлами

## 2. Задачи по дорожкам

### A. Зрение (`feat/vision`)

- **A1. Сегментация под реальное освещение.** Сейчас жёсткие HSV-пороги. Добавить
  нормализацию (CLAHE/баланс белого) и опциональный адаптивный порог; всё — за
  конфигом, не ломая `RouteSpec`.
- **A2. Нумерация маршрутов.** `mars/numbering.py` с протоколом
  `RouteNumberReader`: реализация «из конфига» (сейчас) и «по ArUco-маркерам»
  (`cv2.aruco` установлен, `cv2.ximgproc` — нет).
- **A3. Перспектива и масштаб.** Принять homography от дорожки B (поле/маркеры),
  мерить длину в метрах; сравнить 2–3 метода (скелет, упрощённая полилиния,
  длина после rectify) — это и есть «нетривиальное сравнение» из задания.
- **A4. Пунктирные маршруты.** Как на спутниковом фото: склеивать коллинеарные
  компоненты (дилатация/морфология) до скелетизации, иначе длина занижается.

Проверка: `python3 -m unittest discover -s tests -v`; фикстуры в `tests/fixtures/`
(синтетика + реальные кадры, когда появятся).

### B. Калибровка и данные (`feat/calibration`)

- **B1. `tools/calibrate.py`** — выбрать пиксели на кадре, получить HSV-диапазон,
  сразу вписать в `config/routes.json` (или вывести готовый JSON).
- **B2. `mars/scale.py`** — `px_per_meter` по ArUco-маркеру известного размера:
  `cv2.aruco.ArucoDetector` → сторона маркера в px → масштаб на высоте полёта.
- **B3. Сбор кадров.** `samples/frames/` с именами `frame_<высота>m_<свет>_<дата>.jpg`;
  минимум 3 кадра: ровный свет, тени, блики.
- **B4. Опасный маршрут.** Сопоставить спутниковое фото (белые стрелки между
  ArUco) с цветом/номером на поле и выставить `dangerous: true` в конфиге.
  Сейчас заглушка — синий №3.

Проверка: `python3 main.py --frame samples/frames/<кадр>.jpg --json` даёт
осмысленные цвета/номера; `px_per_meter` не `null`.

### C. Полёт (`feat/flight`)

- **C1. Pioneer SDK 2.** Сверить реальный API (connect/takeoff/go_to_local_point/
  land/camera) с документацией, убрать `TODO` в `mars/flight.py`.
- **C2. `mission.py`.** Цикл: connect → takeoff(H) → goto(точка съёмки) → capture →
  `analyze_frame` → печать ответа → land. Высота и границы — из констант/конфига.
- **C3. Отказоустойчивость.** Нет кадра → повтор N раз → посадка; таймауты;
  `finally: land()`.
- **C4. Симуляция.** `python3 mission.py --simulate --frame ...` проходит без
  железа (использует `SimulatedAdapter`).

Проверка: симуляция зелёная; на площадке — чек-лист (взлёт, кадр, посадка).

### D. Отчёт (`docs/report`)

- **D1.** Структура по критериям `Task2.md`: идея, обоснование, команда, этапы,
  схема алгоритма, что получилось/нет.
- **D2.** Скриншоты: спутниковое фото, кадр с камеры, `--debug-out` разметка.
- **D3.** Таблица маршрутов (цвет, номер, длина) и объяснение метода сравнения.
- **D4.** Экспорт DOCX/PDF.

### I. Интеграция (лид)

- Держит `main.py` и контракт; мержит в порядке **A → B → C → D**.
- Гоняет сквозной сценарий после каждого мержа.
- Обновляет `AGENTS.md` при изменении команд/структуры.

## 3. Фазы

| Фаза | Что происходит | Кто | Выход |
|---|---|---|---|
| **M0** (день 0) | Заморозка контракта, ветки/worktree, зелёный smoke | все | 25 тестов зелёные, ветки созданы |
| **M1** (2–3 дня) | Параллельно: A на синтетике, B на поле, C по докам SDK, D каркас отчёта | A/B/C/D | у каждой дорожки свой PR |
| **M2** | Появились кадры: B калибрует → A переводит фикстуры на реальные → C снимает кадр в миссии | B→A, C | конфиг откалиброван, длина в метрах |
| **M3** | Интеграция: миссия end-to-end в симуляции, ответ в CLI, цифры в отчёт | I | `mission.py --simulate` + `main.py --json` |
| **M4** | Харденинг (плохие кадры, таймауты), финальный отчёт, репетиция полёта | все | отчёт + чек-лист полёта |

Критический путь: **B (кадры) → A (калибровка порогов) → I (интеграция)**.
C и D от него не зависят и стартуют сразу.

## 4. Git-процесс

```bash
# каждому — своя ветка и worktree, чтобы не толкаться в одном каталоге
git worktree add ../v2m-vision      -b feat/vision
git worktree add ../v2m-calibration -b feat/calibration
git worktree add ../v2m-flight      -b feat/flight
git worktree add ../v2m-report      -b docs/report
```

- Ежедневно `git fetch && git rebase origin/main` в своей ветке.
- PR маленькими кусками; ревьюер — владелец затронутых файлов или лид.
- Мерж в `main` — только лид, порядок A → B → C → D.
- Конфликты возможны только в `config/routes.json` (владелец B) и `main.py`
  (лид) — поэтому их правят только они.
- Не коммитить крупные бинарники: кадры держать в `samples/frames/` выборочно.

## 5. Риски и заготовки

| Риск | Ответ |
|---|---|
| Реальных кадров нет | A работает на синтетике; B первым делом снимает кадры |
| Нет доступа к дрону/SDK | C пишет по документации + `SimulatedAdapter`, проверка на площадке |
| Неизвестен опасный маршрут | B сопоставляет спутниковое фото с полем; флаг в конфиге |
| Дрейф контракта | аддитивные изменения, ревью лида, `AGENTS.md` в актуальном виде |
| Разные пороги у A и B | единственный источник истины — `config/routes.json` |

## 6. Определение готовности

1. `python3 -m unittest discover -s tests -v` — зелёный на `main`.
2. `python3 main.py --frame <кадр> --json` — корректный цвет, номер, длина в метрах.
3. `python3 mission.py --simulate --frame <кадр>` — полный цикл без железа.
4. Отчёт собран и экспортирован; чек-лист полёта проверен.
