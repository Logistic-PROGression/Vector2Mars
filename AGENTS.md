## Задача 1 — восстановление JPEG со спутника

Вход — текстовый лог приёмника SDRangel (`map_Rx.txt`). Пакет 74 байта:

| Байты | Поле |
|---|---|
| 0–4 | заголовок `01 02 03 04 05` |
| 5–8 | синхрослово `31 6F 6B 6F` (только пакеты изображения) |
| 9–12 | смещение в файле, **little-endian** |
| 13–14 | номер файла (`06 00`) |
| 15–68 | 54 байта данных |
| 69–71 | резерв (нули) |
| 72–73 | CRC-16 |

Формат лога: строка `[ЧЧ:ММ:СС] ✓ CRC OK` либо `CRC FAIL`, под ней HEX-строка пакета.

Конвейер: оставить `CRC OK` → hex→bytes → проверить синхрослово → `int.from_bytes(b[9:13], "little")` → `buf[offset:offset+54] = b[15:69]` (повторы перезаписывают, так и задумано) → после укладки всех кусков принудительно `buf[0:2] = b"\xFF\xD8"` (передатчик намеренно портит первые два байта JPEG) → запись в бинарном режиме.

Подводные камни: `CRC FAIL` пропускать; big-endian для смещения даёт абсурдные значения; `FF D8` восстанавливать **после** укладки кусков, иначе затрётся.

Запуск из корня репозитория (лог — артефакт, поэтому лежит в `samples/` и не коммитится):

```bash
python3 decode_jpeg.py samples/map_Rx.txt samples/image.jpg
```

Без аргументов скрипт ищет лог в текущей папке (`спутник бурмалдутник.txt`, `map_Rx.txt`, `samples/map_Rx.txt`) и пишет `image.jpg`.

## Задача 2 — БПЛА + OpenCV, поиск кратчайшего маршрута

- Стек по заданию: **Python**, **Pioneer SDK 2** (Пионер Мини 2 / Геоскан), **OpenCV**. Ответ должен содержать цвет, номер и длину кратчайшего маршрута.
- На карте со спутника есть **опасный маршрут, который нужно исключить** из выборки — учитывай это в фильтрах.
- Оценивается нетривиальное сравнение длин, устойчивость к ошибкам (никаких падений, обработка плохих/отсутствующих кадров), читаемость и воспроизводимость судьями без команды.
- Два сложных узла интеграции — полётные миссии и получение кадра с камеры. Держи управление полётом отдельно от зрения, чтобы OpenCV-логику можно было проверять на сохранённых кадрах без железа.

### Каркас и команды

| Файл | Роль |
|---|---|
| `main.py` | CLI: `--frame`, `--config`, `--json`, `--debug-out` |
| `mars/config.py` | JSON → `SceneConfig`/`RouteSpec`, строгая валидация |
| `mars/vision.py` | `analyze_frame`, `annotate`, `skeleton_length_px` |
| `mars/aruco.py` | `detect_markers`, `annotate_markers`: ArUco id, центр, сторона в px |
| `mars/scale.py` | `px_per_meter(markers, marker_size_m)` — масштаб по маркеру (B2) |
| `mars/arrow_routes.py` | `detect_arrow_routes`, `annotate_arrow_routes`: цепочки стрелок между метками (B4) |
| `mars/flight.py` | `FlightAdapter`, `SimulatedAdapter`, ленивый `PioneerAdapter` |
| `config/routes.json` | палитра HSV, `px_per_meter`, `min_area_px`, флаг `dangerous` |
| `tests/` | unittest, без железа |

```bash
python3 main.py --frame samples/frames/frame.jpg --config config/routes.json \
    --debug-out samples/frames/frame_annotated.png
python3 main.py --frame samples/frames/frame.jpg --json
python3 -m mars.aruco samples/image.jpg --out samples/image_markers.png
python3 -m mars.aruco samples/image.jpg --marker-size-m 0.15
python3 -m mars.arrow_routes samples/image.jpg --out samples/image_route.png
python3 -m unittest discover -s tests -v
```

- Нет кадра/конфига → exit 2 и сообщение на русском, без трейсбека. Пустой кадр, шум, `None` → пустой результат, exit 0.
- Пока `px_per_meter: null`, длина выводится в пикселях; после калибровки — в метрах.
- Опасный маршрут сейчас заглушка (синий №3). Реальный назначает спутниковая картинка — перепроверить, когда появятся кадры.
- Длина — по 1-px скелету (морфологический скелет + Zhang-Suen, без `cv2.ximgproc`), диагональные шаги взвешены `sqrt(2)`. Не заменять на `cv2.arcLength` контура: он меряет периметр и завышает длину толстых линий.
- При появлении кадров: положить в `samples/frames/`, откалибровать `hsv_ranges`, `px_per_meter`, `min_area_px`, уточнить `dangerous`.
- ArUco на спутниковом снимке `samples/image.jpg`: словарь `DICT_4X4_50`, id 0 и 2. Детектор (`mars/aruco.py`) не падает на `None`/пустом кадре, неизвестный словарь → `ValueError`. Для реальных кадров словарь и `marker_size_m` перепроверить на поле.
- Опасный маршрут со спутника — цепочка белых стрелок между метками 0 и 2 (3 стрелки, ~140 px), детектор `mars/arrow_routes.py`. Маршрут привязан к паре меток, поэтому несколько маршрутов в кадре не смешиваются; исключать опасный маршрут на поле по этой паре. Пороги масштабируются от стороны маркера.
